# E-0 Encryption Remediation (Development/Testing)

**Scope:** E-0 only, from the encryption and key-management assessment of 2026-11-12. Owner-authorized development task; owner-led review. E-1 to E-10 are not started. Nothing here changes a production or certification gate.

**Formats:** the AES-256-GCM v1 field-value and document envelopes are unchanged and are now pinned by known-answer vectors (E0-6). No envelope v2, provider, key hierarchy or rotation change.

## Requirements

| Item | Change | Where |
|---|---|---|
| E0-1 Worker startup protection | One environment rule for the configured key provider, `EncryptionProviderEnvironmentPolicy`: `LocalDevelopment` is accepted only in Development or Testing (case-insensitive, as `IHostEnvironment`). The Business API guard now delegates to it unchanged. The Worker registers `EncryptionProviderStartupGuard` immediately after its trust-configuration guard and before the business infrastructure and every processing service. Outside Development/Testing the host refuses to start; no provider is substituted. | `Infrastructure/Features/Documents/EncryptionProviderEnvironmentPolicy.cs`, `Api/Composition/DocumentProcessingHost.cs`, `Worker/Composition/EncryptionProviderStartupGuard.cs`, `Worker/Program.cs` |
| E0-2 Document decryption stream | `DecryptAsync` no longer wraps the source in a new `PrefixedStream` per segment. The read-ahead header is carried into the next iteration in a buffer, so every read goes directly to the source and the call depth stays constant. Segment validation is unchanged (length bound, truncation, partial header, final-segment flag, segment index in nonce and AAD). A declared segment length is now compared as an unsigned value, so a header above `Int32.MaxValue` is rejected as ciphertext (`CryptographicException`) rather than surfacing as an `OverflowException`. | `Infrastructure/Features/Documents/AesGcmFileEncryptionService.cs` |
| E0-3 Encryption memory handling | `EncryptAsync`: the DEK is zeroed in `finally` on every exit path, including key-provider, source and sink failures. The two segment buffers are allocated once and swapped; previously a new 1 MiB look-ahead buffer was allocated per segment. The dead zero-length read is removed. | same file |
| E0-4 Decryption failure security event | The field and document decrypt implementations attach a `DecryptionFailure` descriptor to the exception they already throw, without changing its type. The descriptor holds a reason code (`AUTHENTICATION_FAILED`, `KEY_MISMATCH`, `KEY_UNAVAILABLE`, `UNSUPPORTED_ENVELOPE`) and identifiers only. One `DECRYPTION_FAILED` audit event (category Security, outcome Failed) is written once per failure through the existing audit projection, either at the API problem handler or at the document download stream, where the response may already be streaming. Responses, status codes and fail-closed behaviour are unchanged. The event never contains plaintext, keys, key references, wrapped keys, nonces or ciphertext. | `Application/Features/FormRecords/Encryption/DecryptionFailure.cs`, `Application/Features/Audit/IDecryptionFailureRecorder.cs`, `Infrastructure/Features/Audit/DecryptionFailureRecorder.cs`, `Api/Composition/BusinessProblemHandler.cs`, `Application/Features/Documents/Documents/DocumentHandlers.cs`, `Application/Features/FormRecords/History/RestorePlanner.cs` |
| E0-5 Decryption call-site architecture test | An IL scan (Mono.Cecil) of every product assembly, Business and Authority, finds each call to a decrypting operation. That covers the field and document ports and their AES-GCM implementations, the codec's decrypting overloads, data-key unwrapping, and any `System.Security.Cryptography` `Decrypt*`/`CreateDecryptor`. Calls inside lambdas, local functions and async state machines are attributed to their declaring method. The 18 reviewed call sites are allow-listed with the reason each is permitted. A new or removed call site fails the build. | `tests/architecture/.../DecryptionCallSiteTests.cs` |
| E0-6 AES-256-GCM v1 known-answer vectors | Deterministic vectors for field values (two vectors) and documents (0 bytes, 37 bytes, exactly one segment, one segment + 5 bytes, two segments). They cover encryption and decryption, the exact AAD bytes, the wrapped-key format, every AAD component and authentication failures. All expected values were produced independently with Python `cryptography` 50.0.2 (`docs/evidence/e0-encryption-remediation/`). Deterministic cores are internal and reached only through `InternalsVisibleTo`, following the KAT-M1-01 pattern. | `tests/features/.../EncryptionKnownAnswerTests.cs` |

## Notes for the owner

- **E0-2 severity.** Before the change, a document with a few thousand segments overflowed the stack and terminated the process when decrypted (reproduced with 4,000 segments; 300 segments measured a call depth from 208 to 1,404 frames). A 2 GB controlled upload has about 2,000 segments, so large-document downloads may have been near that limit. The regression test now fails with an assertion if nesting returns.
- **E0-4 coverage.** API paths are covered: record read, edit, create, update, history/restore, related forms and document download. The Worker's protection migration and reconciliation already turn a decryption failure into their own explicit failure outcomes and events (for example `DEPROTECT_AUTHENTICATION_FAILED`). They were left unchanged, so the same failure is not recorded twice. The creation-idempotency fingerprint key is not a field or document, and its existing handling is unchanged.
- **E0-4 store.** The event lives in the business audit projection (untrusted projection class), like the other business-side security events. It is not a security incident (PG-056); adding an incident type would need a schema migration and is outside E-0.
- **E0-5 review.** Each call site was checked: every user-facing one follows an Authority-verified read (`VerifiedRecordReader`), restricted to the authorized subset, and the Worker ones run under Authority reprotection commands or the protection-verifier credential. No authorization defect was found.
